\section{Extended Experimental Setup}
\label{sec:s1}

This section gives the rationale and procedural detail behind the setup
in the main text's Experimental Setup section.

\paragraph{CaRB sample.} The 548 CaRB test sentences are those whose text
matches between \texttt{data/CaRB/data/test.txt} and the gold annotation
file \texttt{test.tsv} by exact string. The 93 excluded sentences differ
between the two files in whitespace and quoting; the exclusion is a
pre-existing mismatch, not a selection. The official CaRB scorer's AUC is
a single-point approximation, since the extractors produce one operating
point rather than a confidence-ranked list.

\paragraph{Comparison systems.} \texttt{Babelscape/rebel-large} was
attempted as a CaRB comparison system and found incompatible with CaRB's
open-domain, span-based scoring: REBEL is a closed, Wikidata-schema
relation extractor, so its raw score against CaRB's scorer is not a
meaningful comparison and is not reported. GPT-4o, Claude Sonnet 5 and
Gemini 2.5 Pro were evaluated on the original 30-sentence CaRB pilot
only; Gemini 2.5 Pro needed a 3,072-token output budget and still
returned no valid output for 5 of the 30 sentences. GenIE, InstructUIE, DyGIE++, and TACRED were outside the scope of this evaluation.

\begin{sloppypar}
\paragraph{Code map.} Structured extraction:
\texttt{src/extractors/structured.py}. LLM extraction (product domain):
\texttt{src/extractors/openrouter\_llm.py}. Prompt-parameterised
extraction (CaRB, DocRED, BioRED):
\texttt{src/extractors/openrouter\_openie.py}. Aggregation equations:
\texttt{src/pkb\_math.py}, applied per candidate by
\texttt{src/pkb\_instrumentation.py}; knowledge-base adapter:

\texttt{scripts/dec006\_regenerate\_synth\_data.py}; provenance filter:
\texttt{src/provenance\_filter.py}; fine-tuning:
\texttt{scripts/dec006\_lora\_finetune.py}. Input formats: records for
the product domain and CaRB, JSON for DocRED, PubTator for BioRED.

\paragraph{Product-domain schema.} The generator's 13 predicates are
\texttt{manufactured\_by}, \texttt{belongs\_to\_category},
\texttt{has\_price\_usd}, \texttt{has\_screen\_size\_inch},
\texttt{has\_ram\_gb}, \texttt{has\_storage\_gb},
\texttt{has\_battery\_life\_hours}, \texttt{has\_weight\_kg},
\texttt{has\_color}, \texttt{made\_of\_material},
\texttt{target\_market\_region}, \texttt{supports\_fast\_charging}, and
\texttt{has\_noise\_cancellation}. For each product it draws brand,
category, colour, material, region, and eight numeric attributes from
fixed pools.

\paragraph{Prompts.} The pipeline's extraction prompt is in
\texttt{src/extractors/openrouter\_llm.py}; the fine-tuning
data-generation and evaluation prompt, shared by both so the tasks
match, is \texttt{src/prompts.py}. CaRB, DocRED, and BioRED use
\texttt{prompts/openie\_carb\_v1.txt}, \texttt{openie\_docred\_v1.txt},
and \texttt{openie\_biored\_sent\_v1.txt} (a per-sentence version of the
BioRED pilot's prompt listing all eight relation types where the pilot
listed six); the document-level check uses
\texttt{openie\_docred\_doc\_v1.txt} and \texttt{openie\_biored\_doc\_v1.txt}
(Section~S11).
\end{sloppypar}

\paragraph{QLoRA settings.} Rank 16, $\alpha=32$, dropout 0.05, learning
rate $2\times10^{-4}$, batch size 2 with gradient accumulation 4, bf16.
The leakage-free evaluation selected 8 epochs from $\{2,3,5,8\}$ on its
validation split.

\paragraph{Leakage-free fine-tuning: selection detail.} On the
20-product validation split, a seed-42 epoch search selected 8 epochs
(rank 16, $\alpha=32$, learning rate $2\times10^{-4}$; $F_1=0.744$, ahead
of 5 epochs at $0.722$ and 3 at $0.646$), and a follow-up LoRA search
found no configuration exceeding this default (rank 32 and learning rate
$3\times10^{-4}$ both reached $0.734$, $0.011$ lower, so the
pre-registered $0.01$ tie rule was not triggered). Validation recall was
flat across every configuration with at least 5 epochs
($R=0.593$--$0.600$, 83--84 of 140 gold triples), so selection was
decided by precision alone: the top three configurations were within
$0.011$ $F_1$, separated only by false positives (0 vs.\ 5). Selecting on
$F_1$ therefore chose the most conservative adapter, the one that made
the fewest validation predictions (83).
% [EVID-044]

\paragraph{Leakage-free fine-tuning: pooled scoring convention.} The
pooled figures follow the evaluator's convention of scoring all
products' predictions as one set, in which an incorrect triple repeated
across products counts once. The base model repeats 38 incorrect
triples across products, so its false positives are 99 under this
convention and 137 when each product is scored separately; per-product
counting gives $0.475$ against a seed mean of $0.546$ ($+0.071$,
$p=0.002$), against the reported $0.511$ and $0.553$ ($+0.042$). The
pooled convention is thus the more conservative one for fine-tuning,
and the primary bootstrap, which scores products separately, is
unaffected.
% [EVID-044]

\paragraph{Fine-tuning base model and hardware.}
Mistral-7B-Instruct-v0.3 was chosen over Llama-3.1-8B-Instruct to avoid
a gated-repository approval wait. Training and adapter evaluation ran on
rented RunPod GPUs, mostly an RTX 4090 (24 GB), with an RTX 3090
substituted for some runs after RTX 4090 pods failed GPU sanity checks;
runtime is not compared across GPU types.

\paragraph{Why DocRED and BioRED use $\lambda=0.5$, $\tau=0.70$.} Under
$\lambda=0.5$, the product-domain threshold $\tau=0.88$ would require
four or more corroborating observations (the argument of the
corroboration-requirement proposition with these values), which the
public corpora's evidence structure rarely supplies; $\tau=0.70$ is
reachable with two. The values were set for the DocRED pilot and kept
fixed, not tuned.

\paragraph{The Wilcoxon floor at five seeds.} With $n=5$, the Wilcoxon
signed-rank test cannot report $p$ below $0.0625$, the value reached
when all five paired differences share a sign. A Wilcoxon $p=0.0625$ at
five seeds is therefore the strongest result the test can give, not a
weaker one than an accompanying $t$-test.

\paragraph{Recall denominators in detail.} The offline rule comparison's recall uses the
\texttt{gold\_unstructured} facts of train-split products, built with the
same \texttt{normalize\_gold()} logic as the original run scripts, and
matching the snapshots' own \texttt{gold\_label} column with zero
mismatches on both snapshots. It is directly comparable to the
admission recall of the calibration analysis on the same 657-triple
snapshot at $\tau=0.88$. It is not comparable to held-out extraction
recall, which is
measured on other products from a single extraction pass with no
admission step, or to the closed-loop test's recall, which uses the
larger \texttt{gold\_structured} set (checked against
\texttt{scripts/dec019\_closedloop\_compare.py}).

\paragraph{Cost of the rule comparison.} The comparison is a replay of knowledge-base snapshots
saved by the product-domain runs: it re-scores stored observations under
six rules, with no API calls or GPU time.

\section{Computational Complexity}
\label{sec:formal-analysis-complexity}

The production candidate-acceptance path is empirically $O(N)$ per call
and $O(N^2)$ cumulative over $N$ accumulated observations
% [EVID-036]
, caused by a linear scan over every previously accepted candidate in
\texttt{src/pkb\_instrumentation.accepted\_slot\_keys} on every new
observation -- measured at $72.7\times$ latency growth for $80\times$
more observations
% [EVID-036]
. An indexed alternative (same aggregation mathematics, keyed by
normalized (subject, predicate) slot rather than scanned linearly)
achieves $O(1)$ per call and $O(N)$ cumulative
% [EVID-036]
; it was implemented illustratively but not wired into the evaluated
system. This is not a limiting factor at the scale evaluated in this
paper ($N$ in the hundreds, the main text's Experimental Setup section), where
LLM API latency dominates wall-clock time
% [EVID-036, cross-referenced against DEC-008's linear end-to-end runtime
% finding]
, but is stated here as a forward-looking scalability property of the
current implementation, separate from the aggregation rule's own
mathematical properties above.

\section{Module Ablation: Five-Seed Runs}
\label{sec:s4}

Before the thirty-seed extension, the ablation was run at five seeds
($42$--$46$) at $N=20$ (4 held-out test products) and $N=50$ (10), with
five configurations: the full pipeline, without the feedback controller,
without the probabilistic knowledge base (max-merge), structured-only,
and unstructured-only (Table~\ref{tab:s3-ablation-full}). Neither
ablated variant differed significantly from the full pipeline at either
scale (all $p \ge 0.31$). The direction for the variant without the
feedback controller reversed between scales ($+0.142$ at $N=20$;
$-0.045$ at $N=50$), whereas the max-merge variant scored higher than
the full pipeline at both ($+0.147$; $+0.033$). With five seeds, a paired
$t$-test has 80\% power only for standardised effects of about $1.7$
standard deviations, about $0.29$ absolute $F_1$ at the observed
variance, so these runs rule out only large effects. The structured-only
and unstructured-only variants have no held-out evaluation by design.
% [EVID-020; EVID-039; AUDIT.md]

\paragraph{Standard-deviation correction.} The original run logged these $F_1$
standard deviations as population SDs ($\text{ddof}=0$), e.g.\ $0.0934$
for the full pipeline's held-out $F_1$. The values in
Table~\ref{tab:s3-ablation-full} are converted to sample SDs
($\times\sqrt{n/(n-1)}$, $n=5$; $0.0934 \times \sqrt{5/4} = 0.104$),
matching the project's $\text{ddof}=1$ convention. No mean,
$t$-statistic, or $p$-value changes; only the SD figures do. The same
correction applies to the five-epoch fine-tuning SD in
Section~\ref{sec:s5}.

\section{Superseded Fine-Tuning Exploration (Tuned on Its Own Test Set)}
\label{sec:s5}

\textbf{The results in this section are superseded by the leakage-free,
pre-registered evaluation in the main text (Automated Fine-Tuning Evaluation), which is
negative, and are not a current finding.} They selected hyperparameters
and then tested significance on the same 8-product test set.

\paragraph{The tuning-leakage issue and its resolution.} The epoch and
LoRA grid that selected the 5-epoch configuration, and the five-seed
run that reported $p=0.0028$ for it, both evaluated on the same 8-product
test split. It has 8 products rather than 10 because an automated
leakage guard excludes any test product whose name appears in the
fine-tuning data, and excludes 2 of the 10. There was no independent
validation split separating selection from confirmation. The fix was
pre-registered (select on the 200-product superset's 20-product
validation split, confirm once on its untouched 40-product test split)
and executed as the leakage-free evaluation of the main text, with a
leakage-guard unit test
(\texttt{tests/test\_dec027\_leakage\_guard.py}) that aborts training
before any GPU time is spent if a held-out product appears in the
training data. The one-sample tests below also treat the base score as
fixed, so they capture variation across training seeds but not across
test products, of which there were only 8 (7 base-model true
positives).
% [scripts/dec006_evaluate_adapter.py; EVID-037; Decision log.md, DEC-024, DEC-027; EVID-044]

\paragraph{Results.} Mistral-7B-Instruct-v0.3 was fine-tuned with QLoRA
on the same 90 synthetic examples. The base model (greedy decoding)
predicted 46 triples, 7 of them correct ($P=0.152$, $R=0.125$,
$F_1=0.137$). An earlier evaluation in which two intended test products
also appeared in the training data was withdrawn, and both products
were excluded.
% [EVID-026; EVID-027; EVID-028]
In a seed-42 search, precision increased with training epochs, reaching
$1.000$ at 5 and 8 epochs, while recall stayed at $0.125$
(Figure~\ref{fig:finetuning}a; Table~\ref{tab:s4-epoch-search}). No
alternative LoRA rank or learning rate exceeded the default configuration
(Table~\ref{tab:s5-lora-search}), and recall was $0.125$ in all nine
runs. \textbf{This flat recall does not show that fine-tuning leaves
recall unchanged}: the base model found only 7 of 56 gold triples, so a
loss of about 10\% of true positives, the size measured in the leakage-free evaluation, is
less than one triple and could not appear on this set. Over five seeds
(Table~\ref{tab:finetune-5seed}; Figure~\ref{fig:finetuning}b), with the
configuration tuned on the same test set, the 5-epoch configuration
exceeded the base model in every seed ($\Delta F_1=+0.064$, 95\% CI
$[0.037,0.091]$, $t(4)=6.57$, $p=0.003$), and the 3-epoch configuration
in four of five ($+0.044$, $[-0.005,0.093]$, $p=0.066$); the two did not
differ significantly ($+0.020$, $[-0.045,0.085]$, $p=0.446$).
% [EVID-037; EVID-038; EVID-040]

\section{Protocol Check: Design}
\label{sec:s11}

\paragraph{Configurations.} The check crosses two extractors,
Llama-3.1-8B and DeepSeek-V3.2, with two units, sentence and whole
document, on DocRED and BioRED. The Llama-3.1-8B sentence-level runs on
both corpora and the DeepSeek-V3.2 sentence-level run on BioRED are
reused from the main runs; DeepSeek-V3.2 at sentence level on DocRED was
run on a pre-registered random 400 of the 845 documents, for cost. All
configurations use the main runs' aggregation settings (normalised key,
$\lambda=0.5$, $\tau=0.70$), temperature 0, and R3 as the primary rule.

\paragraph{Document-level extraction.} Each document is sent in one
call with its sentences numbered, using a minimal edit of the
sentence-level prompt. The extractor may extract relations whose
entities appear in different sentences and must list every sentence
that supports each triple. Each cited sentence counts as one source; a
triple that cites no valid sentence gets a single document-level source
and can never be corroborated. Unparsable output is recorded and not
re-requested, and the document then counts as having no extractions.

\paragraph{Verified corroboration.} A gold fact counts as corroborated
when it is recovered from two or more cited sentences that genuinely
support it: gold evidence sentences on DocRED, sentences in which both
concepts are mentioned on BioRED. This stops a model from inflating
corroboration by citing arbitrary sentences. Of the sentences cited for
triples that match a gold fact, 89.8\% (Llama-3.1-8B) and 96.6\%
(DeepSeek-V3.2) met this test on DocRED, and 83.9\% and 81.7\% on BioRED.
$\rho$ divides the corroborated share by the annotation-level rate
(DocRED 50.2\%, BioRED 35.1\%).

\paragraph{Decision rules, fixed before any extraction.} Applied per
corpus to the configuration with the highest corroborated share, with
paired bootstrap CIs over documents (10,000 resamples) against the
Llama-3.1-8B sentence-level configuration on the same documents:
\emph{weakened} if it raises corroboration (CI excluding zero), reaches
$\rho \ge 0.2$, and narrows the gap to no aggregation (CI excluding
zero); \emph{overturned} if, in addition, its own gap CI includes or
lies above zero; \emph{stands} if every new configuration has
$\rho < 0.2$ and a gap significantly below zero on both corpora;
\emph{partial} otherwise. The pre-registration's examples of a partial
outcome include a gap that narrows significantly but stays
significantly negative, which also satisfies the stands rule; the
overlap is reported in the main text.
% [Decision log.md, DEC-033; EVID-048]

\subsection{Dual-Source Extraction}
\label{sec:framework-extraction}

For the product domain, a structured path maps record fields to the 13

general ingestion module and no PDF, DOCX, or SQL support. Supplementary

\subsection{Probabilistic Knowledge Base}
\label{sec:framework-pkb}

Equations~(1)--(2) of the main text are applied to each
candidate, and every accepted observation is kept; no code path deletes
an accepted candidate, so the knowledge base grows monotonically. A
max-merge adapter implements the same interface for the ablation
(Section~\ref{sec:results-ablation}), and a replay module reconstructs
any saved end-of-iteration state from stored observations, for the
closed-loop test and the offline rule comparison
(Section~\ref{sec:results-closedloop} and the main text's empirical
validation of the rule).

\subsection{Feedback Controller}
\label{sec:framework-feedback}

The feedback controller builds the hint that guides re-extraction from
three blocks: missing facts (gold keys not yet
accepted), false patterns (accepted keys not in gold), and
under-covered predicates (fewer than two accepted observations). Every
call site passes it the \emph{training-split gold labels}
% [scripts/dec003_product_probkb_run.py; src/experiment_runner.py]
. The feedback is therefore computed against known answers, not against
any uncertainty or disagreement internal to the knowledge base, so the
loop is not self-supervised: it presupposes labelled training data,
which exists here only because the domain is synthetic
(the main text's Limitations). The original design named these
directions after DySECT's ``Encouraging'' and ``Prohibitive'' modes, but
those labels do not appear in the code, and the false-pattern block
differs in purpose from DySECT's Prohibitive mode
(the main text's section on DySECT).

\subsection{Synthetic Supervision, Provenance Filtering, and Fine-Tuning}
\label{sec:framework-finetuning}

Synthetic fine-tuning examples are built from the knowledge base's
above-threshold triples, grouped per product into the paragraph-in,
JSON-out shape used for evaluation. By default a triple is included only
if at least one of its observations comes from the structured source
(Section~\ref{sec:results-provenance}). Fine-tuning (QLoRA on
Mistral-7B-Instruct-v0.3) is started manually on a rented GPU; no code
triggers it automatically from recall or knowledge-base growth, and
there is no adapter registry or rollback.
% [grep for registry/rollback/auto_trigger across src/ and scripts/: none]

\subsection{What Was Specified but Not Implemented}
\label{sec:framework-gaps}

Six elements of the original design have no code in the evaluated
implementation: KNN-based hierarchical concept abstraction;
automatically triggered fine-tuning; an adapter registry with rollback;
character-level source offsets (provenance is stored as a truncated text
snippet); a human validation interface; and ingestion beyond CSV, JSON,
and plain text. They are scope limits of what this paper evaluates
(the main text's Limitations).


\section{Additional Formal Properties}
\label{sec:s14}

Properties of Equations~(1) and (2) of the main text that the main
argument does not use directly.

\begin{proposition}[Order-invariance]
$A(t)$ depends only on the multiset $\{c_1,\dots,c_n\}$, not on the order
in which observations are accumulated.
\end{proposition}
\begin{proof}
Multiplication is commutative, so $\prod_i(1-\lambda c_i)$ is invariant
under any permutation of the index set $i=1,\dots,n$.
\end{proof}

\begin{proposition}[Monotonicity in evidence]
\label{prop:monotone}
Adding an observation with confidence $c_{n+1} > 0$ to an existing set of
$n$ observations strictly increases $A(t)$; $A(t)$ is non-decreasing in
$n$ and strictly increasing whenever every added observation has
$c_i > 0$.
\end{proposition}
\begin{proof}
Let $A_n = 1-\prod_{i=1}^n(1-\lambda c_i)$. Then
$A_{n+1} - A_n = \prod_{i=1}^n(1-\lambda c_i) \cdot \lambda c_{n+1} > 0$
whenever $c_{n+1} > 0$, since $\prod_{i=1}^n(1-\lambda c_i) > 0$ by the
boundedness proposition above.
\end{proof}

\begin{proposition}[Saturation under repeated observation]
\label{prop:saturation}
If the same confidence $c$ is observed $n$ times, $A_n = 1-(1-\lambda c)^n
\to 1$ as $n \to \infty$, geometrically, at rate $(1-\lambda c)$: the
residual $1 - A_n = (1-\lambda c)^n$ decreases by the constant factor
$(1-\lambda c)$ with every additional identical observation.
\end{proposition}
\begin{proof}
Immediate from Equation~(1) of the main text with $c_i=c$ for all $i$.
\end{proof}


\begin{proposition}[Conflict-penalty properties]
\label{prop:conflict}
For fixed $A(t)$, $C(t) = A(t)/(m(t)+1)$ is strictly decreasing in
$m(t)$, and $C(t) = A(t)$ exactly when $m(t)=0$ (no penalty when the slot
is uncontested).
\end{proposition}
\begin{proof}
$\partial C(t)/\partial m(t) = -A(t)/(m(t)+1)^2 < 0$ for $A(t) > 0$, and
$C(t)|_{m(t)=0} = A(t)/1 = A(t)$ directly from Equation~(2) of the main text.
\end{proof}

\section{Closed-Loop Evaluation: Discussion}
\label{sec:s17}

\subsection{What the Ablations Do and Do Not Show}
\label{sec:discussion-ablations}

Two results bear on whether the Noisy-OR PKB helps. The thirty-seed
ablation rules out an effect of about $0.08$ $F_1$ or more in the PKB's
favour, not a smaller one, and its point estimate favours max-merge
(Section~\ref{sec:results-ablation}). Separately, in the offline replay max-merge exceeded the
published rule at its own selected threshold but not at the shared
$\tau=0.88$, where its significant precision loss and recall gain cancel
in $F_1$ (Table~1 of the main text). Neither comparison
shows that the PKB is unnecessary or harmful, but every comparison
favours max-merge or finds no difference, so the paper cannot claim that
it improves held-out $F_1$. The rival ceiling is one mechanism that can
hold back recall under the Noisy-OR rule but not under max-merge; it has
not been shown to cause the ablation difference. The feedback
controller's ablation is a plain null: neither a benefit nor a cost of
about $0.08$ $F_1$ or more is supported.
% [EVID-045; EVID-041]

\subsection{Why Fine-Tuning Raised Precision but Lowered Recall}
\label{sec:discussion-finetuning}

This is consistent with how the fine-tuning data was built: from the
knowledge base's own high-confidence triples, that is, from facts the
extractor had already found and the PKB had already accepted. Such data
can teach the model to state already-discoverable facts more reliably
and to suppress spurious alternatives, raising precision, but it gives no
exposure to facts the extractor never found, which would be needed to
raise recall. It can also suppress previously recovered true positives
that fall outside the narrower training distribution, lowering recall,
as in every seed of the leakage-free evaluation. That cost was invisible
on the superseded 8-product set, where the base model had only 7 true
positives. Selection also favoured this outcome: validation recall was
flat across configurations, so $F_1$-based selection chose on precision
alone and picked the most conservative adapter. The recall loss explains
the negative per-product result; the positive pooled comparison comes
mainly from false positives removed on products where the base model had
no correct triples. These accounts fit the per-seed detail but do not, on
their own, rule out other explanations.
% [EVID-044]

\subsection{Why Calibration Is Poor}
\label{sec:discussion-calibration}

Two mechanisms are consistent with the poor calibration (ECE $=0.333$;
no correct triples in the $0.6$--$0.7$ and $0.8$--$0.9$ bins). First, the
input confidence is self-reported by the extractor within a
prompt-imposed range, not derived from token probabilities or calibrated
(the main text's Hyperparameters section), so a poorly calibrated output
is expected from the input alone. Second, saturation
(Proposition~\ref{prop:saturation}) applies whether repeated
observations are correct or not, so a repeated incorrect extraction
accumulates confidence exactly like a repeated correct one
(the main text's independence proposition). This fits the two worst bins being
almost entirely single-valued-predicate triples with a median of zero
competing values, the uncontested case in which nothing in
Equation~(2) of the main text can challenge a confidently repeated wrong
answer. Neither mechanism was isolated experimentally.


\section{Closed-Loop Evaluation: Limitations}
\label{sec:s18}

These caveats qualify the results in Section~S16 and moved with them.

\paragraph{The provenance gate was tested against a generator-derived
source.} The filter's rise in precision from $93.5\%$ to $100.0\%$ was
measured with a structured source generated from the same attribute
values as the gold triples (Section~\ref{sec:results-provenance}), so
the structured source was never wrong
% [EVID-029]
. A robustness check partly mitigates this by corrupting the structured
source at 5\%, 10\%, and 20\%: the filter's precision advantage decayed from
$+0.991$ to $+0.823$ (95\% CI $[0.688, 0.911]$) but remained
significant at every rate
% [EVID-042]
. That corruption was random, however, and
an independent real-world structured source may be wrong in correlated
ways that random corruption does not model.

\paragraph{The feedback loop is not self-supervised.} The feedback
controller builds its hint from the training-split gold labels: missing
facts and false patterns are computed against the known answers
(Section~\ref{sec:framework-feedback})
% [src/feedback_builder.py; src/experiment_runner.py]
. The closed loop as implemented presupposes labelled training data,
which exists here only because the domain is synthetic. A deployment
without gold labels would need a feedback signal derived from the
knowledge base itself, which was not built or tested.

\paragraph{Ablation power.} With thirty seeds the module ablation
detects effects of $0.070$--$0.086$ absolute $F_1$ with 80\% power
(Section~\ref{sec:results-ablation}). Smaller effects of the feedback
controller or the probabilistic knowledge base, in either direction,
are not ruled out
% [EVID-045]
.

\paragraph{The closed-loop test is a single seed with a model-family
confound.} The closed-loop integration test used one seed (43, the best
of three in the standalone evaluation) and compared a Llama-3.1-8B
control with a treatment arm fine-tuned from Mistral-7B, so any
difference between the arms cannot be attributed to fine-tuning alone
(Section~\ref{sec:results-closedloop})
% [EVID-030]
. It was not repeated across seeds or with a Llama-based adapter.


\paragraph{Software versions.} No fine-tuning run reported here
pinned the versions of torch, transformers, trl, or bitsandbytes,
including the leakage-free run that supplies the headline fine-tuning
result. Only the PEFT version can be recovered, from adapter metadata
(0.21.0 for every leakage-free adapter; 0.20.0 for the earliest
exploratory adapter). Runs after the leakage-free evaluation record
every installed version
% [EVID-044]
. The API-hosted extractors are fixed by model identifier alone, and
the provider could change the model served behind an identifier.


\paragraph{Unmeasured resource use.} Memory use could not be measured
reliably, because every scale ran in a single process, and GPU
utilisation during fine-tuning was not recorded
(Section~\ref{sec:results-scalability})
% [EVID-023]
. The scalability claims cover runtime only.

\paragraph{An unindexed candidate scan.} The evaluated implementation
scans every previously accepted candidate on each new observation,
which is $O(N)$ per call and $O(N^2)$ cumulative
(Supplementary Section~S3). An indexed variant with
the same aggregation mathematics was benchmarked but not integrated
into the pipeline
% [EVID-036]
. This does not limit the scales evaluated here, where API latency
dominates, but would at larger scale.
